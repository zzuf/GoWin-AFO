# Initial hosted CI failures

The first push passed the ordinary CI matrix, but exposed two independent
environment assumptions in the other workflows.

## CI-SOURCE-001: installed SDK servicing drift

[Generation run](https://github.com/zzuf/GoWin-AFO/actions/runs/35783582263)
failed while fetching WinRT: the runner's `Windows.winmd` SHA-256 was
`11191cbcc796e520d47547b3f986be94a48556fe336d4e63334596d9f31a7806`,
not the locked `e2dee80d011cb9fc1276a0bd9f244f7a58d5ca72fe906a56e90d61c68cf8601a`.
Both SDK installations use the `10.0.26100.0` directory name.

The official SDK CPP NuGet 10.0.26100.8249 reproduces the runner hash.
The official SDK CPP NuGet 10.0.26100.7705 contains the exact old input bytes.
The lock now selects 7705 and verifies archive SHA-256
`ff455660bee071a744715a9665666fa29c07681579d3d815959a9eec5a556424`.
No hash check is disabled, and no API content is upgraded or downgraded.
Nested WinMD paths come from the lock's file list; missing/ambiguous selections
fail. The slice pin is reviewed against the byte-identical payload, and all
derived artifacts are regenerated with the new package provenance.

## CI-ABI-001: hard-coded Visual Studio installation

[ABI run](https://github.com/zzuf/GoWin-AFO/actions/runs/35783582302)
failed before compiling because the Visual Studio 2022 Enterprise path was not
present. The Windows 2025 hosted image
[moved to Visual Studio 2026](https://github.com/actions/runner-images/issues/14017).

The workflow now discovers the C++ toolchain with `vswhere`, retains the fixed
Windows SDK ABI target, and fails explicitly when the requested SDK is absent.
The regression script checks environment propagation for x86/x64 and rejects
missing SDKs and missing locators. ARM64 remains compile-only, not runtime-tested.

## CI-TEST-001: expected failure leaking into the runner exit status

The first corrected hosted run passed ordinary CI, deterministic generation,
x86 ABI execution, and ARM64 compile verification. The x64 setup test printed
success but exited with code 1: its final negative test left `LASTEXITCODE=1`.
The [GitHub PowerShell runner](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax)
propagates that native status after the script returns. The test script now
explicitly returns zero only after all assertions pass; exceptions still fail.
The regression was reproduced with the same runner epilogue, not just by
checking its printed success message.

The source archives and installed SDK are not committed. Coverage regression,
ABI mismatch, and deterministic-generation gates remain enabled; the full-source
coverage baseline is not relaxed for these CI fixes.
